# APP 界面信息分层规范｜L1/L2/L3 隔离（全局默认，单一真源）

> 适用：凡面向用户交付的 APP 与面向访客的网站/页面。非用户界面（内部工具、控制台）不适用。
> 与 `app-theme-i18n.md`（主题＋多语言）、`app-brand-assets.md`（品牌资产）、`app-navigation.md`（导航与视觉方向）并列。
> 本规范**不新增角色、Gate、阶段或 Human Decision**——全部挂既有 Gate。

## 0. 问题与默认继承

**问题**：开发智能体常把内部审查信息、技术约束、风险分析、版本编号、授权流程直接渲染到普通用户界面，导致 APP 冗长、专业、复杂，甚至出现与产品目标无关的**阻断式操作**。

面向用户的产品**自动继承**本规范，不反复问用户。只有用户对某项目明确提出特殊要求，才在该项目 `PRODUCT_PLAN` 记覆盖。

---

## 1. 三层隔离原则

| 层 | 内容 | 呈现方式 |
|---|---|---|
| **L1｜默认可见** | 任务、结果、原因、下一步，以及**当前场景必要**的安全与法律信息 | 直接显示，不折叠 |
| **L2｜主动展开** | 详细玩法、来源依据、适用条件等 | 用户**主动操作**才展开（如"查看来源""展开详情"）。**来源用人能看懂的名称**（如"海南玩法资料"），**不用内部 ID**（不用 `S02`、`evidence_grade=C`） |
| **L3｜仅内部** | Phase、Gate、AC/FR 编号、模型路由、审查评分、**置信度内部等级**、数据 ID、动作代码、开发版本与 hash、运营授权记录 | **只保留在开发/审查/管理资料，不允许默认渲染到普通用户界面** |

**判据**：一个信息如果只对开发/审查/运营有意义、对普通用户完成任务没有帮助，它属 L3，不得出现在用户界面。

---

## 2. 严禁文档文字直接转 UI

Builder **不得**把 `PRODUCT_PLAN`、`UX_CONTRACT`、Research、QA 报告或合规审查中的**原始说明**直接复制到用户页面。需求与证据可以保留，但**必须经过面向目标用户的文案转换**。

**转换对照（P046 实测）**

| 内部写法（禁止直接上屏） | 面向用户的写法 |
|---|---|
| `E01 / DRAW_S2` | 「还差一张二条」 |
| `证据等级 C`／`evidence_grade: C` | 「这套玩法可能因牌桌不同，先向朋友确认」 |
| `Phase 1 原型模拟` | **仅记录在原型 README**，不上屏 |
| `AC-014 关键：是` | 不上屏（属 L3） |
| 内部素材授权流程 | 由**运营或项目负责人**处理，**不自动变成访客必须经过的审批门槛** |

转换要求：说人话、说结果与下一步、去掉编号与等级词、长度按场景裁剪。

---

## 3. 安全、医疗与版权边界（**不得因精简而隐瞒**）

精简文案**不得**用来隐藏：真实危险、必要停止条件、隐私告知、依法必须取得的同意。

但**非紧急说明应按场景渐进披露**，不在首页和每个页面重复长篇免责声明。

- **P045（医疗）**：出现疼痛或明显不适时，**清楚提示停止并提供退出操作**；**不要把整套医学审查逻辑直接放到训练主页**。
- **P037（版权/学生作品）**：区分**项目方在展示或发布前取得必要许可的责任**，与**网站访客实际需要承担的操作**；**没有真实必要性，不得凭内部审核要求增加前台门槛**。
- **P046（玩法依据）**：证据强弱要如实表达，但用用户能懂的话（"这套玩法可能因牌桌不同，先向朋友确认"），不用 `证据等级 C`。

---

## 4. 各阶段前置检查（靠既有 Gate 拦截，**不新增 Gate**）

| 阶段 | 必做 | 拦在哪 |
|---|---|---|
| Product Plan | 明确用户**真正需要看到的结果和操作**；标注哪些信息属 L3 不上屏 | Readiness／关键 AC 集合 |
| UX Contract | 区分**用户可见文案**与**开发内部元数据**（`UX_CONTRACT.json` 显式标记） | UX Gate |
| Prototype | 检查首页／详情／设置／异常状态是否被**技术术语、审查内容、免责声明占据** | Prototype Gate |
| Design Freeze | **冻结用户文案层级与展开方式**（哪些 L1、哪些 L2、怎么展开） | Freeze Gate（COPY/COMPONENT Freeze） |
| Code Reviewer / QA | **扫描真实渲染页面中的内部标识**，同时做**人工语义核验** | 关键 AC 证据 |

---

## 5. 自动扫描（提示用，不机械禁用）

可用脚本扫描**真实渲染页面/原型源码**中的可疑内部标识，命中即**提示**交由既有审查与返工机制处理：

`AC-\d+`、`FR-\d+`、`INT-\d+`、`ST-\d+`、`SCR-\d+`、`Phase \d`、`Gate`、`evidence_grade`、`证据等级`、`置信度`、`DRAW_S\d+`、版本号 `v?\d+\.\d+\.\d+`、长 hash、动作代码。

**必须避免误伤**——下列**不得**被机械拦截：

- 正常的**地区玩法名称**（如"四川""海南""广东"）与**玩法版本**（真实用户需要的规则差异）
- **查看来源**功能与其链接（人可读名称即可）
- **必要的安全/法律/隐私提示**与停止条件
- 真实用户界面上的**"来源""版本""风险"**等普通词汇——**不得因为含这些字就禁用**

**处置**：自动扫描命中只是**提示**，是否上屏由 QA／Code Reviewer 结合场景**人工语义核验**判定；未达标准走**原有审查与返工机制**，**不新增角色、Gate、阶段或 Human Decision**。

---

## 6. 与既有体系的关系

- 本规范是唯一真源；`PRODUCT_PLAN`、`UX_CONTRACT`、Freeze **记录**其中的分层要求，**不另建一套真源**。
- 文案语言规范仍以 `app-theme-i18n.md`（`zh-CN`＋`en`）为准；本规范只管**哪些信息该出现在界面上**。
- 存量项目的整改由**该项目编排者**在既有开发链内做局部修正，**全局管理者不越过编排者直接改业务代码**。
