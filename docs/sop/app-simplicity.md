# APP 产品简化门槛（单一规则真源）

> 2026-10-10 用户定。**不新增角色、独立 Gate、Phase、账本字段、状态枚举或评分指标。**
> 四项审查全部挂在既有环节：Readiness／Design Freeze／DEV_BASELINE／QA。
> 配套静态提示工具 `scripts/model/simplicity-probe.mjs`（若入库则为**提示型**，只报线索，不判 Gate）。

---

## 1. 目的与总则

**在投入大量开发成本之前，先确保产品足够简单、清楚、好用。**

工程流程能保证「正确实现设计」，**不能保证「设计本身简单好用」**。本门槛补的就是这一问：
**这些是不是多余的？**

**三条总则**

1. **以真实用户操作为准。** 按钮数、页面数、状态数、代码行数**只能作为调查线索，不得作为判定依据**。
2. **没有冗余时允许报告「无须删减」，不得强制制造删减项。**
3. **安全、隐私、异常恢复与数据正确性不因简化而丢失。**

---

## 2. 统一判定口径

| 判定 | 含义 |
|---|---|
| **PASS** | 核心任务清楚，没有明显不必要的复杂度 |
| **CONDITIONAL** | 存在局部问题，**必须写明整改项 ＋ 复验条件 ＋ 复验人** |
| **FAIL** | 存在严重入口重复、主任务不清、非必要阻断、导航混乱或明显过度设计 |

**严重问题（上述五类）不得以 CONDITIONAL 绕过冻结门槛。**
需要例外时，必须给出**产品理由、影响面、明确的 Human Approval**。

**不得机械规定**所有产品只能有几个页面、几个按钮。
复杂度须与**真实用户需求、使用频率、产品风险**相匹配。

---

## 3. 豁免清单（下列情形一律不得判为冗余）

- 安全／医疗的**停止条件、风险告知、退出路径**
- **隐私告知**与依法必须取得的同意
- **空状态**（无数据时的必要说明）
- **删除确认**与不可逆操作的二次确认
- **数据完整性**校验
- **异常与中断恢复**路径

> 简化门槛**只删"多余的"，不删"必要的"**。
>
> **豁免的是「安全信息本身」，不是「安全相关的界面」。**
> 安全／医疗能力不得随意删除；但其**页面排版、提示时机与操作流程仍可接受简化审查**——
> 只要不损失安全性，Gate B 照常检查该页面是否有重复入口、不必要跳转或非必要阻断。

## 4. Gate A｜产品范围与 MVP 审查

**挂点**：Phase1 **Readiness Gate**（不新增 Gate）
**负责人**：planner 审查 ＋ builder 拟稿（均为现有角色）
**输入**：Product Plan 草案

| # | 判定项 | 通过条件 |
|---|---|---|
| A1 | 核心任务 | 能用**一句话**说清用户最常做的那个任务 |
| A2 | 高频功能 | 已列出用户最常用的功能，且与 A1 不冲突 |
| A3 | MVP 边界 | 已写明「必须包含」，每项都能对应到 A1 或 A2。**轻量项目一句话回答即可** |
| A4 | 可延后／隐藏／取消清单 | 已列出；**轻量项目一句话回答即可**；确认无冗余时**可写「无须删减」并给简单理由**。**`Out of Scope`（列出「不做什么」）不得直接代替本项**——本项要列的是**已纳入范围里可延后／可隐藏／可取消**的部分 |
| A5 | 交付形式 | 已判断网页／PWA／原生 APP 哪种更轻更合适，并给理由 |
| A6 | 治理强度分级 | 已按 §5 逐条写明五项依据 |

**A3／A4 不强制新建独立表格**：可直接写在 Product Plan 本节内，或引用既有段落。

**失败处理**：缺任一项 → Readiness 不满足 → 打回 builder 补，**不进 Human Review**。
**复验**：planner 按上表逐项复核，可直接引用 builder 原文作答。

---

## 5. 治理强度分级

**不得仅凭「单屏」「单任务」决定。** 必须综合以下五项：

| 维度 | 低 | 高 |
|---|---|---|
| 安全风险 | 无健康／资金／隐私风险 | 涉及疼痛、停止条件、隐私、资金 |
| 设备能力 | 标准设备即可 | 需传感器／蓝牙／后台常驻 |
| 数据敏感度 | 本地无敏感数据 | 健康、生物、身份数据 |
| 异常恢复 | 中断后可重来 | 中断需恢复进度且不可重来 |
| 用户操作复杂度 | 单指单步 | 多步、多屏、强时序 |

| 级别 | 管线 |
|---|---|
| **轻量** | Product Plan 精简版 ＋ 原型 ＋ QA 体验验收；可跳过完整 UX 双审与 SDD 全链 |
| **标准** | 现有全链不变 ＋ 简化门槛 |
| **复杂** | 现有全链 ＋ 简化门槛全项 |

**轻量管线可以减少的**：文档篇幅、重复审查轮次、双审份数、SDD 任务拆分粒度。

**轻量管线不得减少的（五类必要验收）**：
1. 安全告知与停止条件　2. 隐私与授权　3. 数据正确性　4. 异常与中断恢复　5. 真机基本可用性

## 6. Gate B｜UX 信息架构简化审查

**挂点**：**Design Freeze 之前**（不新增 Gate）
**负责人**：product-reviewer（现有角色，Phase1 末尾双审位）
**输入**：UX Contract ＋ 可运行原型
**必产交付物**：**《可删减项清单》**——可为空，空须写「无须删减」及依据

| # | 判定项 | 通过条件 |
|---|---|---|
| B1 | 首页主任务 | 首页**一眼能看到**核心任务的主动作 |
| B2 | 同状态重复入口 | **同一状态下**不存在两个用途相同的入口 |
| B3 | 高频被低频挤占 | 高频任务**未被**低频选项挤压或前置 |
| B4 | 非必要跳转 | 核心任务**无需多余跳转**即可完成 |
| B5 | 术语负担 | 用户**不需理解过多术语**即可操作 |
| B6 | 返回路径 | 返回路径符合用户预期 |
| B7 | 非必要阻断 | 弹窗／提醒／恢复状态**未无必要地阻断主任务** |
| B8 | 可简化空间 | 已评估能否合并页面、减少常驻控件、隐藏高级设置**而不损失核心能力** |
| B9 | 文案与跳转一致 | 按钮文案与实际跳转目标一致 |

**豁免**：适用 §3 豁免清单。

**失败处理**：**核心任务仍有明显非必要复杂度 → 判 FAIL，不得 Design Freeze。**
**复验**：对整改项逐条复验，**只复验整改项，不重跑全表**。

## 7. Gate C｜SDD 实施前防膨胀检查

**挂点**：**DEV_BASELINE 确认之前**（不新增 Gate）
**负责人**：planner（Phase2 审 PLAN）＋ code-reviewer

| # | 判定项 | 通过条件 |
|---|---|---|
| C1 | 新增界面元素 | TASK **未新增**原型／UX Contract 之外的页面、按钮、设置项 |
| C2 | 内部状态上屏 | **未把**技术内部状态暴露为用户页面 |
| C3 | 文案控件堆砌 | **未为满足 AC** 不断堆入说明文字与控件 |
| C4 | 主路径偏离 | **未偏离**已批准的主要用户路径 |
| C5 | 未批准交互 | **未出现**原型未批准的新交互负担 |

**变更分级**

| 情形 | 处理 |
|---|---|
| 入口合并、布局简化、局部交互修正（**不改核心业务规则**） | 走**已有局部变更流程**，**不强制 Change C** |
| 涉及需求范围、关键行为或安全边界变化 | 按**现有变更分级**处理（Change C 受控重开） |

## 8. Gate D｜QA 真实使用体验验收

**挂点**：Phase2 **产品验收追踪矩阵**（不新增 Gate）
**负责人**：qa ＋ supervisor 抽查

| # | 判定项 | 取证方式 |
|---|---|---|
| D1 | 首次使用能否看懂 | 真机／浏览器首次进入录屏 |
| D2 | 高频任务几步完成 | 实际点击路径 ＋ 步骤数记录 |
| D3 | 主按钮是否一眼可见 | 首屏截图 |
| D4 | 页面切换与返回 | 录屏 |
| D5 | 暂停／恢复／中断连贯 | 录屏 |
| D6 | 是否被说明文字淹没 | 截图 ＋ 人工判读 |
| D7 | 过度滚动／拥挤／遮挡 | 截图 ＋ 人工判读 |

**证据按风险分级（不做一律最严）**

| 风险级别 | 场景 | 证据要求 |
|---|---|---|
| **低** | 普通 UI 文案/样式/布局改动 | **足以复核结果的证据**（改动点前后截图或差异说明即可） |
| **中** | 涉及多屏导航、复杂交互、状态切换 | **完整操作路径**（录屏或逐步点击记录，覆盖关键路径与返回路径） |
| **高** | 安全停止、异常恢复、数据正确性、隐私授权 | **严格取证**（真实截图＋录屏＋实际操作路径，且须覆盖失败与中断场景） |

**禁止**：用测试通过率、单测结果、代码审查结论或 AC 数量**替代**用户体验验收——但**取证强度按上表分级，不要求所有改动都提交全套截图录屏**。

**必要的安全信息不得删除**，但允许在**不降低安全性**的前提下优化展示方式（如渐进披露、分层呈现、默认展开必要项），照 `docs/sop/app-ui-layers.md` L1/L2 分层执行。

**失败处理**：任一不通过即返工；**复验须重录该场景**，不接受文字描述替代。

## 9. 静态提示工具的定位

`scripts/model/simplicity-probe.mjs`（如入库）为**提示型**：

- **只报线索，不判 Gate，不自动决定放行与否**
- **不能代替人工语义审查或真机 QA**
- 必须明确区分五类对象：**条件互斥分支**（`cond?A:B` 只渲染其一）、**同屏并存**、**异常分支**（空态／错误态）、**原型演示产物**、**真实生产控件**
- **原型中的演示选项不得混作生产缺陷**
- 能力不支持时输出 `UNSUPPORTED`，**禁止零识别假通过**

## 11. SOP 依赖判定（Skill 执行时的五种情形）

本节是 `docs/sop/app-*.md` 被 Skill 引用时的**统一判定口径**，
`SKILL.md` 依赖声明与 `validate_skillset.py` 均以此为准。

| # | 项目副本 | 母版 | 判定 | 处置 |
|---|---|---|---|---|
| 1 | 缺失 | 可读 | **允许回退母版** | **不判** `DEPENDENCY-MISSING`；正常读取母版 |
| 2 | 有 | 可读但**内容不一致** | **`DEPENDENCY-STALE`** | 按**单一真源与版本冻结规则**处理（以母版为准，或由编排者决定冻结项目版本）；**不静默使用旧规则** |
| 3 | 有且可用 | 不可读 | **允许读取项目副本** | 读取，但**必须标明「无法核对母版最新状态」** |
| 4 | 均不可读 | 均不可读 | **`DEPENDENCY-MISSING`** | **仅当本任务确实需要该 SOP 时**，报缺失并**阻断相应审查步骤**；不得以默认值继续、不得标记 PASS |
| 5 | — | — | **本任务不需要该 SOP** | **一律不检查、不阻断**，不得影响无关工作 |

**单一真源**：SOP 全文只存母版 `docs/sop/`。项目副本是分发快照，**不构成第二真源**。
