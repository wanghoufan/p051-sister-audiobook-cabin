# 后台服务管理规范

## 1. 适用范围

管理智能体创建、启用或改动的、会在当前任务结束后继续运行或自动启动/重启的服务，包括登录项、LaunchAgent/LaunchDaemon、计划任务、守护进程、后台 watchdog 及 Docker 常驻容器。

用户只要求运行或测试时，默认以前台临时方式启动；任务结束时停止。任务结束后仍运行、登录/开机自启或自动重启，需要用户明确授权。

## 2. 创建与登记

1. 创建前检查登记簿、系统后台项、Docker/Compose 服务和端口，确认没有可复用的同一服务，避免重复创建。
2. 先向用户说明项目、目的、后台方式、启停时机、重启方式、监听地址/端口和清理边界；获得明确授权后才实施。
3. 在电脑治理仓库根目录的 `后台服务登记表.md` 登记后，才能创建或启用服务。登记簿无法访问或更新时，不得先创建后台服务。
4. 登记字段至少包括：唯一 ID、可读名称、所属项目/路径、创建来源（智能体及任务）、目的、运行方式、启动/重启条件、端口、数据/日志位置、启停/禁用方式、健康检查、授权依据、状态和最近核验时间；新增、变更、停用、退役写入变更记录。秘密不得入表；来源不明写“待核实”。

## 3. 命名

名称必须明确指出项目与用途，且能与实际配置一一对应。服务 ID 应唯一稳定；LaunchAgent/LaunchDaemon 的 `Label`、plist 文件名和登记 ID 保持一致。系统可见名称及包装脚本使用可读名称，不能只显示 `bash`、`npm`、`python`、`zsh` 等通用进程名。示例：`com.local.prompt-manager.dev`，显示名 `prompt-manager-dev`。

## 4. Docker 去重

已由 Docker Compose 管理的同一服务，登记其 Compose 项目、容器/服务名和重启策略即可；Docker 已负责容器生命周期时，不另建重复的 macOS 登录项、LaunchAgent 或守护脚本。Docker 容器仍需登记。未经授权不得更改重启策略、停止/删除容器，或删除 Volume、挂载数据和备份。

## 5. 启动核验与定期排查

启动后核对登记 ID、实际运行状态、日志、端口及健康入口，并回填结果。定期把系统自启动项和 Docker 常驻服务与登记簿逐项对照，记录新增、重复、来源待核实和已无用途的项目。排查不另建自动运行的后台服务。

## 6. 停用与退役

按唯一 ID 准确定位，只停用用户指定的服务，核实其不会继续自动拉起，并将登记状态更新为“已停用”或“已退役”，保留变更记录。停用不等于删除源码、配置、日志、业务数据、Docker Volume 或备份；删除这些内容须有单独明确授权。
