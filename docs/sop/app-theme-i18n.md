# APP 基础能力规范｜主题 ＋ 多语言（全局默认，单一真源）

> 定位：`docs/sop/` 基础设施规范位。**所有面向用户的 APP 默认继承本文**，不反复询问用户；仅当用户对某项目明确提出特殊要求，才在该项目 `PRODUCT_PLAN` 记录覆盖。
> 适用范围：Android / iOS / Flutter / React Native / React / PWA，以及面向用户交付的纯 HTML APP。
> 不新增 Skill、角色、顶层状态或 Human Gate。缺强制交付内容时，由现有各阶段原有 Gate 拦截。
> 需求真源仍是 `PRODUCT_PLAN`（FR/AC 单真源），本文**不建立第二套需求编号**。
> **姊妹规范**：`app-brand-assets.md`（APP 品牌资产：中文名／英文名／安卓图标／启动画面——P045 实战暴露的漏项）。两者同属 APP 前置，**互相独立但都要在 Phase1 落实**；启动画面底色须与本文的主题三态兼容。

---

## 0. 默认继承与覆盖

| 项 | 默认值 | 覆盖规则 |
|---|---|---|
| 主题 | `SYSTEM` | 用户对某项目明确要求才覆盖 |
| 语言 | `FOLLOW_SYSTEM` | 同上 |
| 初始语言集 | `zh-CN` ＋ `en` | 同上 |

- **Planner/Builder 不得自行取消默认要求**；项目要裁剪必须由用户提出，并在 `PRODUCT_PLAN` 的「APP 基础能力声明（覆盖记录）」写明。
- 覆盖只允许**加**（如增 ru/ko/th 资源、收窄语言范围），不允许在没有用户指令时**减**掉默认的三主题态与中英双语。

---

## 1. 主题规范

三态：`LIGHT` / `DARK` / `SYSTEM`，**默认 `SYSTEM`**。

1. 所有页面与组件共享**统一主题体系与语义化颜色 Token**（不逐页硬编码颜色）。
2. **沉浸式页面（训练/播放/专注等）不得擅自强制深色或浅色**；用户选 `LIGHT` 就保持 `LIGHT`，选 `DARK` 就保持 `DARK`，`SYSTEM` 下跟随设备外观。用户选项优先级高于页面偏好。
3. `SYSTEM` 须随设备外观变化自动更新，无需重启。
4. 设置**持久化**，重启后保持。
5. 切换主题**不得重置**业务数据、进度或当前操作状态。
6. 文字、图标、背景、卡片与各交互状态（hover/pressed/disabled/focus）的对比度与可读性须检查。

## 2. 多语言规范

### 2.1 语言集与回退

- **初始只做两种**：`zh-CN`（简体中文）、`en`（English）。**当前不制作 ru/ko/th 的翻译内容。**
- 设置项三选：`FOLLOW_SYSTEM`（默认）/ 简体中文 / English。
- **系统语言不支持时统一回退 `zh-CN`**（不出现空白、不回退 en）。
- **可扩展架构是硬性验收条件**：未来要加 ru/ko/th 时，**只新增语言资源与必要适配，不得要求重写核心业务架构**。把"资源机制已就绪"作为 AC，不留到后续再重构。

### 2.2 实现要求

1. 使用**官方或成熟国际化框架**（见 §3.2）。
2. 文案与业务逻辑**分离**，使用标准语言资源。
3. **禁止**到处写死 `if 中文 / else 英文`。
4. 覆盖范围：页面、按钮、提示、错误、空状态、安全说明、通知、**无障碍标签**。
5. 切换语言**不丢业务状态与用户数据**。
6. 语音类 APP：语音指令一并本地化；须检查语言、发音、语速、节奏与失败回退。

## 3. 成熟框架优先，禁止重复造轮子

### 3.1 先查已有，再决定

必须**先检查项目已有技术栈、组件与依赖**，再对主题与多语言各条给出判定：

| 判定 | 含义 |
|---|---|
| `REUSE` | 直接用项目里已有的现成能力 |
| `ADAPT` | 对已有能力做最小改动适配 |
| `REVIEW_FOR_REUSE` | 疑似有成熟方案，待评估确认 |
| `BUILD` | 确认无成熟方案，才自研 |

- **禁止**为实现主题与多语言而无理由重构项目、替换技术栈或自研基础引擎。
- 正式库版本、License、维护情况等仍由既有 Reuse Audit 按设计管线既定顺序确认（**不取消、不提前、不另立同名流程**），本规范不提前锁死具体版本。

### 3.2 按技术栈的优先候选（**候选，非无条件安装**）

| 技术栈 | 优先候选 |
|---|---|
| Android Kotlin | Jetpack Compose、Material 3、Android 官方字符串资源与单应用语言能力 |
| Flutter | `ThemeMode`、`flutter_localizations`、`gen-l10n` |
| React / PWA | 现有组件库主题能力 ＋ i18next 等成熟国际化方案 |
| 纯 HTML APP | 现有 CSS Token、`prefers-color-scheme`、轻量成熟本地化能力 |

判定依据是项目**实际已有**依赖，不是这张表的字面照抄。

## 4. 各阶段前置检查（靠现有 Gate 拦截，不新增 Gate）

| 阶段 | 必须产出 |
|---|---|
| `PRODUCT_PLAN` | 「APP 基础能力声明」字段完整（平台/主题三态/语言集/默认/跟随系统/回退/持久化/扩展机制），并落成正式 FR/AC |
| Design Research | 主题与多语言的成熟产品做法、官方平台最佳实践；**不得把主题或语言当成独立产品方向** |
| A/B/C 视觉方向 | 每方向至少展示**浅色＋深色**代表性核心页面；提前查英文长文本布局适应性；A/B/C 仍是三种产品设计，不是三种配色 |
| UX Contract | 主题/语言设置入口、默认值、手动切换、跟随系统、中文兜底、持久化、跨页一致性、**切换时状态保持**、未来加语言的资源机制；**不制造冗余 State** |
| Prototype（Human 2 前） | **真能操作**三主题态与三语言项；切换后核心页面/提示/操作一致；语音类验对应语言语音体验；**模拟系统行为与真实设备能力必须明确区分**；静态效果图不算运行 PASS |
| Human 2 前检查 | 核心页面、异常状态、**文字溢出**、语音体验 |
| Design Freeze | 冻结浅/深双套语义 Token、主题切换规则、支持语言与兜底规则、文案资源与布局原则、已批原型与证据 |
| SDD / PLAN / TASK | 落成实施任务，优先官方成熟组件，不重写基础设施；沿用现有基线机制 |
| Traceability / QA | FR/AC → UX → TASK → TEST → EVIDENCE；见 §5 最小验证集 |

## 5. QA 最小验证集

主题、语言、跟随系统、设置保存、核心流程与状态保持**必须有实际测试证据；没有证据不得宣称通过**（静态检查不算）。

至少覆盖：

1. 三种主题模式（`LIGHT` / `DARK` / `SYSTEM`）均可达且生效一致。
2. 中文与英文均可用；**不支持的系统语言回退 `zh-CN`**。
3. 系统主题变化、系统语言变化后 APP 跟随更新。
4. 设置重启后保存（重启后仍为用户所选）。
5. 页面切换一致性（跨页主题/语言一致）。
6. **英文长度、字体、溢出**（长文本布局自适应）。
7. 语音本地化（语音类 APP 适用）。
8. 切换主题/语言过程中**状态与数据不丢失**。
9. 沉浸式页面遵守用户所选主题，未擅自强制另一态。

采用**代表性关键流程测试**，不机械穷举无意义组合。

- 本规范是 `docs/sop/` 基础设施规范位文件，母版与两分发包由 `scripts/_sync-packages.py` 同步。
- 各阶段强制点落在既有 Skill 与既有 Gate 上（见 §4），**不新增 Skill、角色、顶层状态或 Human Gate**。
- **依赖边界（2026-10-08 澄清）**：Design Pipeline 七颗 Skill（`design-reference-research`／`visual-direction-exploration`／`ux-interaction-contract`／`interactive-product-prototype`／`design-freeze`／`requirements-traceability`／`orca-design-pipeline`）**不随本治理模板包分发**，它们装在 Skill 体系里（中央 Skill 仓库 → 各 Agent 目录）。
  ⇒ **只用本模板包时，APP 基线的机器强制点只有两层**：①`PRODUCT_PLAN` 模板的「APP 基础能力声明」字段；②`scripts/model/check-ledger.mjs` 的 `APP-BASELINE-MISSING`／`APP-CRITICAL-AC-EMPTY`／`APP-CRITICAL-AC-INCOMPLETE`（2026-10-08 起为 FAIL）。
  ⇒ 装了七颗 Skill 时，才额外获得 §4 表中「Design Research／A/B/C／UX Contract／Prototype／Freeze」各阶段的 `BLOCKED` 拦截。**未装时不报错**，只是那些阶段无机器门——这是可选增强，不是缺失。
- 既有运行正常的项目**不批量重构**；是否接本文由该项目在 `PRODUCT_PLAN` 决定。
